# Backlog de Tarefas (`tasks/`)

Esta pasta guarda o **backlog granular** derivado do plano técnico.

Você vai criar aqui, no Module 04:

- `weather-app-tasks.md` — lista de tarefas pequenas, independentes e
  testáveis, organizadas por entrega e prontas para serem delegadas a um agente.

As tarefas **consomem** o plano (`plans/weather-app-plan.md`) e guiam a
implementação (Modules 05–08).

## Status das tarefas

O status de cada tarefa é registrado no próprio `weather-app-tasks.md`:

- `[ ] Não verificada` — os critérios de aceite ainda não foram confirmados;
  pode haver implementação parcial ou código existente.
- `[x] Concluída` — todos os critérios de aceite foram atendidos e as validações
  aplicáveis passaram.

Ao concluir uma implementação, atualize o status da tarefa na mesma alteração
que contém o código e os testes. Se algum critério ou validação estiver pendente,
mantenha a tarefa não verificada e informe o que falta. Não marque tarefas
concluídas apenas porque o código existe.
